# Capture, transcripts and history

Audio capture and discovery, the transcript, history database, status, recording and the MCP server. Code and tests outrank this page.

| Path | Holds |
| --- | --- |
| `crates/app/src/capture.rs` | One capture thread per source (app process tree or mic), 16 kHz mono via Windows autoconvert. Each wake reads every packet Windows has ready (silent packets as zeros), in MMCSS's Audio class; a capture ends when stopped or when its app exits, and hands chunks to a bounded queue that drops audio rather than block |
| `crates/app/src/processes.rs` | Process snapshot, an app's root process (which per-app capture targets), exe paths |
| `crates/app/src/sessions.rs` | Lists apps with an active audio session, and subscribes to Windows' session news (a session opened, started or stopped playing) and device news (added, removed, new default) so discovery runs the moment something changes |
| `crates/app/src/main.rs` | Wiring. Discovery runs on news (session and device notifications, a capture ending, captioning stopping or starting), with a pass a minute as a safety net: it keeps the mic on Windows' default device and a capture per playing app that isn't blocked (none in dictation only mode, where the decoder drops the mic's audio unless the captions key is held), releases an app's capture after a quiet minute, at once when it is blocked, and every capture while stopped, and retries a failing source after 2 s, doubling up to 5 min. The decoder gates audio, leaves out silence once speech detectors are done with it, turns it into captions (each revision of a line through the word rules for its app, before captions, History and the MCP get it; dictation is queued as heard and the panel applies dictation's rules), and swaps models when asked (each stream opens telling voices apart as its source's switch says, the mic's `voices.mic`, an app's `voices.apps`, and a switch changed at run time reloads the model when its speaker model must be added (once downloaded) or dropped, else reopens the streams concerned, also when the place voices are recognised in changed); each stream opens knowing its place's voices (`open_stream_knowing`), its lines' labels become the run's voice numbers through `Session::number_lines`, and the speakers' prints are handed back to the session when a stream ends (`retire`) and every 3 minutes, which also names the voices the panel asked to (`keep_voices_current`) and gives the transcript the saved voices' names (`Captions::set_names`); models load with the word rules' `@` words, and a changed list goes to the engine, which applies it from the next phrase or is loaded again; a pick still downloading waits, and with no model installed it waits for one. With `engine.where = host` it first loads the pick on the host (`remote::connect`; the model needn't be on this PC, and this PC's GPU checks don't apply); failing that it runs here, says so once, and tries the host every minute on a thread of its own (an answer is taken only if the code and pick still match), also from `load_or_wait` when nothing could load; a lost host reloads on the host, then here. Before using the GPU it checks the driver, the GPU build and pack (hashed once, then remembered) and free GPU memory; any failure there or in the helper's test load (the model on the GPU hearing the test clip, before the switch) runs the model on the CPU. Every fallback (GPU to CPU, or another installed model when the picked one can't load) is told once in plain words with what to do: the panel's notice, a tray balloon when the panel is hidden, and the log |
| `crates/core/src/captions.rs` | The transcript: a section per app with its full history, and the permanent You section with every mic line; mic lines also join the pinned apps (`pinned`, by label) whichever window is in front, or with none heard yet the app in front (the decoder names it as `keys::focused_app` does); a restarted app reuses its section; the decoder says where each stream's voices are recognised (`set_stream_place`) and a `Caption` keeps that place, so a saved voice's name (`set_names(section, place, names)`, `set_mic_names`) replaces its label, earlier lines too, only on lines of that place (changing `voices.recognise` never relabels earlier lines with the other place's names; a name always shows, even for a section's only voice, except the mic's first voice, which is always "You"; a rename bumps the section's revision so `changed_since` sees the relabelled lines); a `Caption` has the `voice` of its `Line` and a label, which `display_text` puts first: in an app's section "Speaker N: " (voice + 1) once its own lines carry two or more distinct voices (earlier lines get theirs then), one narrator stays clean; at the mic "You" for the first voice and "Mic 2", "Mic 3"... (in the You section too once it holds two voices; your copies in apps always); each section counts its revisions and dropped lines, and stamps lines so the panel finds the changed ones by binary search. A line also knows whether its label is a saved voice's name (`is_named`), whether it is said into your mic (`mine`, which picks its label style), its `tag` (an unnamed speaker is its number, "3") and whether its voice can be named (`nameable`: not the first voice at your mic) |
| `crates/core/src/subtitles.rs` | Captions mode's model: the newest lines (apps and you, not your copies inside apps) added or revised since a mark, interleaved by time; its settings (`subtitles.*` lines: on, rows, fading when quiet, the pills' opacity for any theme, font and size, and where it was dragged), kept whatever the theme as they are about legibility. A line's colours are always the app theme's |
| `crates/core/src/history.rs` | The transcript database, `%APPDATA%\kiku\transcripts.db` (SQLite, WAL, FTS5): `speakers` (you, or an app) and one row per line with session, time, speaker id and, for your lines, the speaker id of the app you were talking to; queries by speaker, conversation (an app plus your replies), time, session and words (the last word optionally a prefix, for typing), paged with `before`; `matched_words` says which words a search matched, for highlighting; deleting old lines, and a session's (a running session keeps its row). `read_sql` holds the rules for SQL typed by an agent or the user, shared by the MCP server and the app: one statement that only reads, at most `SQL_MAX_ROWS` (300) rows, stopped after `SQL_TIMEOUT` (5 s). Lines saved with a save button (`by_hand`) are never deleted for age. The schema is versioned with `PRAGMA user_version` (migrations in order; databases from before versions are at 0). WAL with synchronous=NORMAL, checkpointed at 256 pages and cut back to 1 MiB. Old lines are deleted in batches; `reclaim_space` VACUUMs only when free pages are a quarter or more and at most 32 MiB of data is left. `open_read_only` is for the MCP server |
| `crates/core/src/status.rs` | What Kiku is doing right now (captioning, model, where it runs (`runs_on`: this PC or the host's address), dictating, save mode, each app and the mic: captured now, last heard, lines this run), written by the decoder to `%APPDATA%\kiku\status.json` on change (at most every 2 s) and every 30 s, removed on quit. No caption text, so manual save mode keeps lines off the disk |
| `crates/core/src/recording.rs` | Saves lines to the database: in auto mode as they finish, in manual mode what a save button asks for; written every 5 s, and at once on stop, model switch, a save button and quit (the decoder finishes each line in progress first); in auto mode deletes lines past the kept days, 1000 per decoder tick, keeping lines saved by hand; gives deleted space back at start when worth it; if the database can't be opened it retries every minute and keeps at most 10,000 lines waiting |
| `crates/core/src/transcripts.rs` | Transcripts as text: `shared.txt` (last ✨) for the MCP server, the transcript saved with a miss, and history lines formatted for reading; local dates and day starts. `replace` writes a file atomically; settings use it too |
| `crates/core/src/misses.rs` | Ctrl+Win+B: each live source's last 30 s of audio and the transcript, saved to `%APPDATA%\kiku\misses` for replaying a missed word with `asr_bench` |
| `crates/core/src/bin/kiku-mcp.rs` | MCP server (stdio) letting agents read Kiku: this session, search by words/speaker/conversation/time, speakers, sessions, ✨ shares, `get_status` (live state from `status.json`), `describe_database`, and `query_database` (their own SQL, under `history::read_sql`'s rules), and three macro tools over `custom\` and `words.txt` through `macros::Customization`: `list_macros` (names, phrases, apps, modes, step kinds, on/off, never text or values), `check_customization` (every problem with `file:line`) and `try_phrase(phrase, app)` (the plan, text masked; a `run` step shown as its program file). They only read: approving commands and the program switches are the app's. A database reader: one read-only connection kept open, never creates or migrates. Every answer is a page of at most 300 lines, rows, sessions or speakers that says how to read the next (`before=<id>`, `from_line` for shares). MCP 2025-06-18 lifecycle. An optional argument names a database to read instead, e.g. a copy for testing |
| `skills/kiku/SKILL.md` | Agent skill for the MCP server: when to reach for it without being told, which tool fits which question, token budgets, SQL examples, and how to edit `words.txt` (kept in step with `words::ASSISTANT_INSTRUCTIONS`). Keep it in step with `kiku-mcp`'s tools. Installed for Claude Code in `~/.claude/skills/kiku/`; uploaded to Claude Desktop as a zip. `skills/kiku-macros/` makes and fixes macros: its `references/macros.md` is `crates/core/src/macros/readme.md` copied (a test in `macros/book.rs` fails when they differ), installed and zipped the same way |
