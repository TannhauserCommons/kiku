# Engines and models

Speech-to-text engines, the helper process, models on another computer, voices, the catalog, downloads and imports. Code and tests outrank this page.

| Path | Holds |
| --- | --- |
| `crates/core/src/paths.rs` | The app's data folder: `%APPDATA%\kiku` on Windows, `~/Library/Application Support/kiku` on macOS, `~/.local/share/kiku` on Linux; and the per-user models folder, `%LOCALAPPDATA%\kiku\models` on Windows (`KIKU_MODELS_DIR` overrides it, e.g. to try downloads) |
| `crates/core/src/engine.rs` | Backend-neutral speech-to-text trait. Add a model family as one module plus one `Backend` variant. Line ids need only be unique per stream; a `Line` has a `voice` (its speaker, a label per stream) when voices are on, else `None`. `open_stream_with(voices)` opens a stream that tells voices apart or not (`open_stream()` is with, when the model can; a stream without builds no tokens and embeds nothing). `open_stream_knowing(known)` opens one with voices that begins knowing the given `Known` voices (labelled 0, 1, ... in that order), and `EngineStream::voice_prints` hands back the speakers' prints and the audio each absorbed (`None` for a stream that tracks none: voices off, Moonshine, a model on a host, which ignore `known` and never receive a print). A `ModelSpec` carries the speaker model's path (`voices`, set when a speakers switch is on and the model is here) and hotwords (words to listen for, each with a boost); `set_hotwords` changes them from the next phrase, or says the model must load again with them |
| `crates/core/src/engine_host.rs` | Models run in a helper process (`crates/core/src/bin/kiku-engine.rs`) driven over pipes, CPU ones too so a crash in ONNX Runtime (one was seen in its Conv kernel) ends only the helper, and because NVIDIA's libraries keep ~1 GB of RAM until their process ends (hotwords go with the load, and changes as a request of their own); unloading ends the helper, and a helper that ends on its own (a driver reset, a crash) has the model loaded again. `engine::load` always uses it (`load_here` loads in this process: the helper itself and `--probe`); the footer and `footprint` count its CPU, GPU and memory. Of its ~1 GB, ~0.2 GB is DLL pages, ~0.25 GB session state and ~0.5 GB GPU kernels loaded on first use (lazily: pinned with `CUDA_MODULE_LOADING`); ~3 GB more is committed but never touched (Windows' backing for GPU memory). The helper finds DLLs only next to itself and in System32 (`SetDefaultDllDirectories`), carries the speaker model's path in the load frame as a last line `voices <path>`, written only with voices on (a helper from before skips it like a hotword line it can't read, and without voices the frame is byte for byte as before), opens a stream with a byte of 1 after its id only when it tells voices apart (`encode_open`; the id alone as before otherwise, and a reader from before stops at the id), carries `Line.voice` after a reply's lines (a voice plus one each, 0 for none, written only when some line has one, so a reader that stops after the lines still works and voices off is byte for byte as before), carries the voices a stream should know after the voices byte of its OPEN (`encode_open_knowing`, only the helper is sent it: the remote client uses `encode_open` alone) and answers a PRINTS request with a stream's speakers' prints, answers a load only after the model heard the bundled 4 s clip (`assets/probe.wav`, public domain LibriVox), and is given 90 s. On Linux a GPU load first checks what ONNX Runtime's CUDA provider needs (`check_cuda_provider`: CUDA 12.9's runtime, cuBLAS, cuRAND, cuDNN 9, a driver that sees a GPU and supports 12.9), because ONNX Runtime otherwise drops the provider and runs on the CPU without a word; it fails with the reason and what to install. `--probe <backend> <dir> [vad]` tries an imported model on the CPU and prints what it heard, since sherpa-onnx ends the process on a model it can't read. `--serve` makes it a host (`remote/host.rs`) |
| `crates/core/src/remote.rs`, `crates/core/src/remote/` | The model on another computer (opt-in; Kiku is otherwise offline). A host's code, `kiku://<address>:<port>/#<fingerprint>.<secret>` (`HostCode`; its `Debug` hides the secret, and nothing may print or log it): the SHA-256 of the host's self-signed certificate and a 32-byte secret, both unpadded base64url. `connect` (5 s to connect, TLS 1.3 pinned to the fingerprint, then the secret) loads a `ModelRequest` (catalog id, device, whether voices are on, hotwords) on the host; a last line `voices` asks for speakers (a host from before it skips the line, no hotword being a single word, and sends none; a client from before it never asks), the host loads its own copy of the speaker model, or captions without voices when it lacks one (said on its stderr), and lines come back with the same trailing voices as the helper's; an OPEN carries the same voices byte as the helper's. `host.rs` is `kiku-engine --serve [--listen <addr:port>] [--state <folder>]` (default `0.0.0.0:7300` and `%APPDATA%\kiku\host`, which keeps `cert.der`, `key.der` and `secret`; it prints `kiku-host <code>`, attaching to the parent's console if run from one): a connection gets 5 s for TLS and the secret (a watchdog shuts the socket, as per-read timeouts can't stop a client sending a byte at a time; at most 16 at once, a wrong secret answered after 500 ms), then one of 4 places, a `HostedEngine` of its own (the model by id from the host's own models, the error naming those it has), at most 64 streams, and a pump thread that keeps reading while a worker drives the engine; each load writes one stderr line, `load <id> on the GPU|CPU: ok in 1.2 s` or `failed in ...: <error>`; silent for 30 s, it is dropped. The network protocol is the helper's frames, with 16-bit audio, replies carrying their stream id, a ping, and frames capped at 16 MiB. `client.rs`: one thread owns the TLS stream, so `push` and `poll` only touch memory (poll returns what has come back, never waiting; `flush`, `open_stream` and `set_hotwords` wait); the client pings after 5 s of sending nothing and the host is lost after 15 s of hearing nothing, a read or write error, or 32 MiB queued. `crates/core/tests/remote.rs` holds its acceptance tests (the fast ones need nothing; the `#[ignore]`d ones Parakeet Unified) |
| `crates/app/src/hosting.rs` | Sharing this PC's models (`host.on`): runs `kiku-engine --serve` while on, keeps its code in `Controls`, restarts it if it ends (2 s doubling to 5 min), ends it with Kiku (a job object too); New code deletes its `secret` and restarts it |
| `crates/core/src/voices.rs`, `crates/core/src/voices/` | Telling voices apart inside one stream (`.loop/voices/`: the benchmark's numbers and decisions). `Embedder` (NVIDIA TitaNet-small through sherpa-onnx, the middle 3 s of a phrase), `Clusterer` (online, per stream, starting from the `Known` voices it is given (a print and its own similarity bar) as its first labels: nearest centroid over a cosine of 0.4, or the known voice's bar, and 0.05 clear of the second best, else a new speaker; it keeps the seconds each speaker absorbed, `heard_voices`; labels once given never change; a part under 1.5 s takes the nearest known speaker or the previous label), `Windows` (0.7 s embedding windows over a phrase: where consecutive ones stop matching, similarity under 0.25, the speaker changes, and the mean of those inside a part is its voice) with `split_points` and `split_text` (the phrase's text cut at the change by the model's token times, words never cut), `join_same_voice`, and `Labeller` (one stream's phrase to `Part`s, each with its voice: the one path for the engine and `voices_bench`), `into_lines` (parts as complete lines in time order with fresh ids). `Segmenter` and `overlaps` (pyannote segmentation-3.0) find overlap offline but don't ship. Voices are on for a stream opened with voices (`Engine::open_stream_with`) when `ModelSpec.voices` names the speaker model (`catalog::speaker_model`, `titanet-small`, loaded by `PhraseEngine`, in the helper or on a host; one that won't load means voices off, logged, and the model still loads); off, nothing here runs or loads. A voice print is biometric: embeddings and centroids stay in memory and are never logged or printed (`Print`'s `Debug` hides the values); a print is written only through a `VoiceStore` (the app's `crates/app/src/voice_store.rs`: `%APPDATA%\kiku\voices.dat`, encrypted with DPAPI for the Windows user and written atomically with `transcripts::replace`; a file that can't be read or decrypted is renamed `voices.dat.bak`, replacing an older one, before a new one is written, and that is logged without content) and crosses only the local pipe to the model's helper (an OPEN carries the voices a stream should know, a PRINTS request brings back its speakers' prints), never the remote protocol: with the model on a host there are no names and no memory across streams, and its lines keep the host's own labels. **Named voices and the run's voices** (`.loop/speakers/NAMES.md`, N1-N9): `voices/book.rs` holds the saved voices a user named (`VoiceBook`: id, name, `Print`, seconds heard capped at 10 min, `VoiceScope` everywhere or one app and `home`, the app it was named in, which "only in this app" limits it to; its byte format, never reusing an id; `VoiceStore` for the bytes, magic `KVB2` (`set_aside` keeps an unreadable store as a backup; `refusal` says why nothing is saved this run), `MemoryStore` for tests and tools; `VoiceInfo`/`SavedVoices::list` is the listing without prints; `SavedVoices`, the shared book that stores every change, with the panel's naming requests), `Place` (the mic, an app, or all apps when `voices.recognise = across-apps`). `voices/session.rs` is the decoder's memory of this run (never saved): `Session::follow` gives a new stream the voices of its place to know (saved ones in scope with `NAMED_SIMILARITY` 0.45, then the most recently heard unnamed ones, up to `Bars::seeds` = 16, with `SESSION_SIMILARITY` 0.55), `number_lines` turns the stream's own labels into numbers that hold for the whole run (`line.voice` becomes the voice's number minus one; a stream that tracks nothing keeps its labels), `hand_back` (when a stream ends and every 3 minutes) folds what a stream heard into the run's voices and the saved ones (a mean weighted by the audio each rests on; a speaker's `HeardVoice` carries the sum of the audio it absorbed, without the known voice it began as, so only the audio since the last hand-back is folded), `name` saves an unnamed voice (keeping its number, with the app it was named in) or renames a named one, `names` gives a place's names for the transcript. Measured by `voices_bench --method names`. `voices/metrics.rs` and `voices/conversation.rs` are the benchmark's scoring and seeded conversations (`crates/core/examples/voices_bench.rs`, data kept outside the repository) |
| `crates/core/src/moonshine.rs` | Moonshine backend over its C API; restarts long streams to bound Moonshine's per-poll cost: at a pause after 32 lines, or mid-line after 64 when the audio never pauses, replaying the line in progress under its id |
| `crates/core/src/sherpa.rs` | sherpa-onnx models that transcribe whole phrases (NeMo and icefall transducers such as Parakeet, NeMo CTC, Paraformer, SenseVoice, Whisper, Moonshine v1): phrases cut by a Silero speech detector (each transcribed with 0.5 s of audio before and after it, since the detector misses soft starts and fading last words), shown once each phrase ends (with voices on, `Labeller` then gives each phrase its speakers and cuts it where they change, and its lines are the parts: `Phrase.parts`; the model's tokens are collected only then, so voices off costs what it did); speech that runs 10 s without a pause (people talking over each other: the detector's own limit only raises its threshold, and Parakeet hears nothing in a phrase that long) Kiku cuts itself at the quietest 0.1 s of its last 4 s, and the detector starts again from there (`crates/core/tests/phrase_cut.rs`). A phrase carries its tokens' times when they spell its text, for splitting it by voice (accuracy over speed; no streaming transducers). Files are found by sherpa-onnx's names (`encoder.int8.onnx`, `tiny.en-encoder.onnx`, `encoder-epoch-99-avg-1.onnx`), int8 preferred on the CPU and avoided on the GPU. A NeMo transducer given hotwords decodes with modified beam search, the words going with each phrase's stream (a new list needs no reload; none at all is greedy search again, a reload); sherpa-onnx splits them into tokens with a SentencePiece vocabulary made from `tokens.txt` (scored minus the id, kept in the temporary folder by content hash). each word's boost goes with it as sherpa-onnx's score (`Lull :2.5`); toward 4 words start to be heard where they weren't said, and a hotword decoded twice or more in a row (beam search repeats boosted words) is written once |
| `crates/core/src/catalog.rs`, `crates/core/catalog.json` | The models offered, bundled as JSON (no remote catalog): family, languages, licence, components needed (`silero-vad`), whether it listens for hotwords (only Parakeet Unified, where they were measured), and variants per device and precision with peak RAM and VRAM and files pinned by URL (Hugging Face `resolve/<commit>/`, or `{release}/` for files published with Kiku's releases, `{releases}/download/models-v1`, now only Unified fp16; `{releases}` is `update::releases()`: the build's `KIKU_RELEASES` unless a manifest moved it), size and sha256; plus the components, the speech detector, the speaker model (`titanet-small`, `nemo_en_titanet_small.onnx` at the models folder's root, 40 MB, Apache 2.0 as the NeMo toolkit; a download of its own, `Target::Component`, `speaker_model()` says where it is once it is downloaded and its hash checks, and no button queues it yet) and the GPU pack. The GPU pack's DLLs are entries in NVIDIA's cudart, cuBLAS and cuDNN zips and Microsoft's ONNX Runtime GPU zip (byte-identical to sherpa-onnx's), pinned by the offset and size of their compressed bytes: 1.6 GB downloaded, 2.4 GB installed. cuFFT, `cudnn_cnn` and `cudnn_ext` are never loaded; cuFFT (287 MB) is left out, the two small ones kept. Imported models join at runtime; settings keep an id, Parakeet Unified when none is saved. When the model picked can't load, Unified on the CPU or any other installed model runs (`download::fallback`); with none installed, settings open on Listening. Models are found in the per-user folder, then `models` next to the app and in the working folder. Moonshine is CPU-only (int8, its runtime crashes on CUDA); Parakeet TDT v2 runs int8 on the CPU and fp16 on the GPU; v3 (25 languages) runs int8 and fp32; Unified int8, fp32, and fp16 (`scripts/make-fp16.py`: same WER, half the VRAM, ~50 ms slower per line on an RTX 3090), picked when the card has under 8 GB. `scripts/catalog.py hash` refills sizes and hashes from local files; `stage` gathers the files published with Kiku's releases (CI's `scripts/publish-models.ps1` makes and publishes them). `Model::installed` checks the folder of the variant for the device picked |
| `crates/core/src/download.rs` | The download button's worker: one thread, ureq with rustls. A model's variant comes with the components it lacks (the GPU pack on the GPU). Files go to `<root>/.staging/<job>/` as `.part`, resume with Range (only a 206 with a matching Content-Range is taken), a zip entry's bytes come by Range and are inflated, each is checked against its sha256, and each folder is renamed into place once all are in. Free space is checked first; network errors retry four times. The queue is kept in `downloads.json` in the models folder and comes back paused. The GPU pack goes next to the app, since ONNX Runtime loads its CUDA provider from its own folder. `fetch_speaker_model` queues `titanet-small` unless `catalog::speaker_model()` finds it whole (the panel calls it at start, once speakers are switched on and in setup's model step when one is on); no model requires it, so a missing speaker model never stops one counting as installed or runnable |
| `crates/core/src/imports.rs` | Importing a model folder: its file names say what it could be (or which unsupported kind it is: GGUF, `.nemo`, PyTorch weights, ...), each possibility is tried with the helper's `--probe`, and the first that hears the clip gets `imported/<id>/model.toml` in the models folder. The files stay where they are; removing it forgets it |
| `crates/core/src/hardware.rs`, `crates/app/src/hardware.rs` | What the PC can run. The app finds threads, memory, the NVIDIA card and driver (DXGI), the CUDA version the driver supports (nvcuda's `cuDriverGetVersion`, no GPU context) and free GPU memory (NVML; DXGI's budget ignores other apps). Core recommends Parakeet Unified, the default model: fp32 on an NVIDIA GPU with a CUDA 12 driver and 8 GB (the GPU pack downloading with it), int8 on the CPU otherwise, saying why up front (no card, old driver, too little memory) in setup and the GPU card |
| `crates/core/src/models_cli.rs`, `crates/core/tests/engine_cli.rs` | `kiku-engine`'s commands for a host with no settings window: `--models` (one line per catalog model: id, name, and per device `installed`/`not installed` with size and precision), `--download <id> [--device cpu|gpu]` (queues the build and the components it lacks on the app's `Downloads`, so resume and sha256 checks are the same; progress every 2 s; `already installed` when nothing is missing; an unknown id lists the catalog's; never the Windows GPU pack, Linux takes CUDA from the system) and `--check [<code>] [--model <id>] [--device cpu|gpu]` (tries a host from the other side, printing its address and never its secret; the code may come from `KIKU_HOST_CODE`). `engine_cli.rs` holds their acceptance tests (the ones needing models or the network are `#[ignore]`d) |
